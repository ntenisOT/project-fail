## Transport evidence

At 17:37:43 the market server closed with 1013 `slow consumer: send buffer
full`. Immediately before it:

- application queue high-water was 27 of 8,192 for the interval;
- maximum application residence was 4 ms;
- the Python runner used about 13% CPU;
- the host was 95-97% idle with about 14.5 GB memory available.

After reconnect, source-event age reached 4.968 seconds while application
residence remained at or below 5 ms. This rules out our measured strategy queue
and gross host saturation, but it does not yet distinguish WebSocket-frame
parsing/scheduler stalls from upstream delivery. Gen67 records frame/event
counts, JSON parse peaks, and event-loop scheduling lag without changing any
strategy parameter.

Normal event age remained about 8-13 ms median. One second is not baseline;
the tails are real and fail closed.
